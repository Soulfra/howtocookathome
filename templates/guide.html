The Big Picture

Your project folder is your restaurant kitchen. Everything you cook (code, files, configs) lives there. Here's how the pieces map:

Your Kitchen (Working Directory) — The folder on your computer. Where you actually do the work. Just like your physical kitchen — messy, in-progress, real.
Technical: this is your local file system, the folder you see in Finder/Explorer.
Your Recipe Book (Git Repository) — Git watches your kitchen and remembers every version of every recipe you've ever written. Burned the sauce? Go back to last Tuesday's version.
Technical: the .git folder inside your project. Created with "git init".
The Pass (Staging Area) — Before you write a recipe into the book, you put finished dishes on the pass. "These are ready to be recorded."
Technical: "git add" moves files to the staging area.
The Safe (GitHub Remote) — A fireproof copy of your recipe book stored off-site. If your kitchen burns down, the recipes survive.
Technical: a GitHub repository. "git push" sends your commits there.
A Test Kitchen (Branch) — You try a new taco recipe without touching the main menu. If it works, merge it back. If it flops, close that kitchen — main menu untouched.
Technical: "git checkout -b name" creates a branch.

Daily Service: The Basic Workflow

This is the flow you'll use 90% of the time. Think of it like closing out a shift.

Kitchen TermCommandWhat It Does

Send to the safegit pushUpload to GitHub

Pro tip: The commit message is your shift note. "Fixed the queso recipe" is good. "changes" is not. Future you will thank present you.

Test Kitchens: Branches

Branches let you experiment without risking the main menu. The main branch (master) is your live menu. Everything else is a test kitchen.

Kitchen TermCommandWhat It Does
Open a test kitchengit checkout -b new-tacosCreate + switch to new branch
Go back to maingit checkout masterSwitch to main branch
List all kitchensgit branchShow branches (* = you're here)
Merge test into maingit merge new-tacosBring the test recipe into the main menu
Close test kitchengit branch -d new-tacosDelete branch after merging
Careful: Always switch to master before merging. You merge into wherever you're standing. Think: "I'm in the main kitchen, bring me what's in the test kitchen."

86'd It: Fixing Mistakes

86 = restaurant code for "we're out" or "kill it." These commands undo things.

Kitchen TermCommandWhat It Does
Take off the passgit restore --staged fileUnstage (don't delete, just un-ready)
Toss today's editgit restore fileRevert file to last commit
Undo last entrygit revert HEADNew commit that undoes the last one
Stash it for latergit stashTemporarily shelve changes
Bring stash backgit stash popRestore shelved changes
Key difference: git restore throws away changes (like tossing a bad batch). git revert records the undo (like writing "removed bad queso from menu" in the recipe book). Revert is safer because you have a record.
